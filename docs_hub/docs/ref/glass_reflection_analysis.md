# 유리문 난반사 문제 분석 (2026-04-29)

## 문제 상황

- **발생 위치**: 긴 복도로 나가는 길목의 유리문 근처
- **현상**: LiDAR 난반사로 인해 자유 공간에 대형 노이즈 클러스터가 찍힘 → global costmap에 허위 장애물 생성 → 전역 경로 재계획 반복 → 로봇 제자리 회전
- **특이점**: 유리 앞에서 멈추는 것을 보면 유리 자체 인식은 정상. 난반사에 의한 유령 포인트가 문제.
- **노이즈 패턴**: RViz 확인 결과 isolated 포인트가 아닌 **대형 덩어리 클러스터** 형태로 지속 발생

---

## 검토한 소프트웨어 해결책과 한계

### 1. Keepout Filter

**개념**: 별도 마스크 맵으로 특정 구역에 항상 LETHAL_OBSTACLE을 강제 주입 → 전역 경로 계획에서 해당 구역 제외

**한계**:
- obstacle_layer의 동적 마킹을 막는 게 아니라 경로 계획만 막음
- 해당 구역이 실제 통과 경로라면 목적지까지 경로 생성 불가
- 난반사 자체를 해결하지 못함

**의미 있는 포인트**: keepout_filter를 inflation_layer 앞에 배치하면 raytrace clearing에도 지워지지 않음 (레이어 순서상 마지막 덮어쓰기)

---

### 2. Static Layer 순서 변경 (obstacle → static)

**개념**: plugins 순서를 `["obstacle_layer", "static_layer", ...]`로 변경 → static_layer가 나중에 max combination으로 덮어써서 raytrace clearing에도 정적 벽 유지

**작동 원리**:
```
obstacle_layer: raytrace → FREE(0)
static_layer (combination_method: 1, max): max(254, 0) = 254 → LETHAL 복원
```

**한계**:
- 지도 후보정(유리문 벽 연장)으로 이미 해결한 **유리 투과 문제**에 대한 해결책
- 난반사로 인한 obstacle_layer의 **동적 마킹 자체**는 막지 못함
- AMCL도 같은 map.pgm을 사용하므로 인위적 벽 추가 시 위치추정 성능 저하 가능성

---

### 3. laser_filters — angle_filter (각도 기반 필터)

**개념**: 특정 각도 범위의 LiDAR 빔을 차단

**한계**:
- 로봇 프레임 기준 고정 각도 필터링 → 로봇 방향 전환 시 필터 위치도 같이 회전
- 유리를 못 보는 사각지대 발생 → 충돌 위험
- **채택 불가**

---

### 4. laser_filters — speckle_filter

**개념**: 주변 인접 포인트 없이 고립된 포인트를 노이즈로 제거 (방향 무관)

**한계**:
- 이 현장의 노이즈는 isolated 포인트가 아닌 **대형 덩어리 클러스터**
- 덩어리 클러스터는 neighbor 포인트가 있어서 speckle_filter가 걸러내지 못함
- **채택 불가**

---

### 5. 맵 좌표계 기반 스캔 필터 노드

**개념**: 각 LiDAR 포인트를 TF로 map 프레임 좌표로 변환 → 사전 정의한 노이즈 구역 폴리곤 안에 들어오면 inf로 마스킹 → `/scan_filtered`로 publish → obstacle_layer는 필터링된 스캔 구독 / AMCL은 원본 /scan 유지

**angle_filter와의 차이**:
```
angle_filter:  로봇 프레임 기준 → 방향 바뀌면 무용지물
map-frame 필터: 맵 프레임 기준 고정 폴리곤 → 방향 무관
```

**한계**:
- 해당 구역에서 실제 동적 장애물(사람)이 나타나도 무시
- 학원 복도에서 학생 충돌 위험 → **안전 문제로 채택 불가**

**변형 시도 — 거리 + 구역 조합 필터**:
```
노이즈 구역 안 AND 거리 > 유리까지 거리  → 반사, 필터링
노이즈 구역 안 AND 거리 < 유리까지 거리  → 실제 장애물, 통과
```
- 반사 포인트는 유리 경로 + 반사 경로 합산으로 유리보다 먼 거리에 찍힘
- 이론상 동적 장애물 감지와 반사 필터링 동시 가능
- **현실적 한계**: 유리 각도에 따라 반사 geometry가 달라져 임계값 정밀 보정 어려움. 오설정 시 사람 못 보는 상황 재발.

---

### 6. do_beamskip vs raytrace — 혼동 정리

| 파라미터 | 소속 | 역할 | 이 문제에 효과 |
|---------|------|------|--------------|
| `do_beamskip: true` | AMCL | 맵과 불일치하는 빔을 **위치추정** 가중치에서 제외 | 없음 (costmap과 무관) |
| `clearing: true` + raytrace | obstacle_layer | 빔 경로를 FREE로 지워 오래된 장애물 제거 | 없음 (반사가 매 스캔 재마킹하므로 clearing 속도로 따라잡지 못함) |

```
/scan
 ├── → AMCL (do_beamskip 적용) → 위치추정에만 영향
 └── → obstacle_layer (raytrace 포함) → costmap에 영향 (반사 포인트 그대로 마킹)
```

---

## 결론

순수 소프트웨어로는 아래 두 가지를 동시에 만족하는 방법이 없음:
- 반사 노이즈 제거
- 동적 장애물 감지 유지

**채택 결정: 물리적 해결**

유리문에 반사 방지 필름 부착 → LiDAR 반사 강도 감소 → 노이즈 클러스터 감소 → 소프트웨어 문제 소멸

소프트웨어 해결책을 배제한 근거:
1. 파라미터 수정만으로는 obstacle_layer 동적 마킹을 막을 수 없음
2. 스캔 필터링은 동적 장애물 회피 안전성을 훼손함
3. 거리+구역 조합은 반사 geometry 의존적이라 현장 적용이 불안정함
